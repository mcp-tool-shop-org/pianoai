# Study-swarm: singing models as of 2026-09-05 — research grounding for the vocal route

**Why this exists.** The Director approved "guide track + ElevenLabs Speech-to-Speech on
Comfy Cloud" as the next vocal route, then asked for an Opus study-swarm because the studio's
June-2026 ruling ("only DiffSinger honors MIDI, and it is blocked on a commercial-safe
checkpoint") could be stale. Five Opus lanes ran in parallel (2026-09-05), each held to the
study-swarm citation standard. Zero cloud credits were spent. This file is the grounding; the
architectural lock is at the end.

## Research grounding (finding → design implication)

**F1. A score-conditioned, English, Apache-2.0 singer now exists.** *SoulX-Singer* — Soul AI
Lab, 2026-02, arXiv:2602.07803 (https://arxiv.org/pdf/2602.07803; repo
https://github.com/Soul-AILab/SoulX-Singer; weights https://huggingface.co/Soul-AILab/SoulX-Singer).
Score-conditioned (MIDI notes + lyrics) or melody-conditioned (F0); Mandarin/English/Cantonese;
zero-shot timbre from a reference clip; Apache 2.0 on **code and weights**; ships `infer.sh`,
a web UI and a MIDI editor. In VocalRender's own benchmark (F2) it is the strictest
score-follower measured: note-timing IOU 0.63 and raw pitch accuracy 0.77, best of five systems.
→ *Implication:* the singer takes the committed score clock directly (pitch, onset, duration
per syllable). No guide track, no voice conversion, no prompt-craft. **The June ruling is
stale on this point.**

**F2. The best-sounding 2026 SVS deliberately refuses score durations.** *VocalRender /
VocalRender-Pro* — Chen, Wang, Mu, Yang, Chng, 2026-07-30, arXiv:2607.27768
(https://arxiv.org/html/2607.27768). Best WER and SingMOS, but "jointly determines local timing
and total output duration during generation… no explicit duration predictor"; Mandarin-only
evaluation; license unstated. → *Implication:* disqualified for a 40 ms onset gate. Expressive
rubato is the enemy of a clock.

**F3. Full-song music models still cannot take a MIDI melody.** ACE-Step 1.5 (ACE Studio +
StepFun, 2026-01, MIT, arXiv:2602.00744) accepts tags/lyrics/BPM/key/duration/audio reference
only; its "generate vocal from MIDI" request (github ace-step/ACE-Step-1.5 issue #926) was
closed as not planned. DiffRhythm 2 (ASLP-lab + Xiaomi, Apache-2.0, arXiv:2510.22950) removes
timestamp labels by design. YuE unchanged since 2025-01. Stable Audio 3 (2026-05, arXiv:2605.17991)
has audio-derived melody conditioning, instrumental-oriented, no melody-accuracy metric. Lyria 3,
Suno v5.5 Cover, MiniMax, ElevenLabs Music: audio-reference "cover" control only. → *Implication:*
**the June ruling on music models is still true.** They stay out of the vocal path; ACE-Step
remains a candidate for beds, not voices.

**F4. The 2026 literature splits the problem exactly the way this repo does.** *MIDI-Informed
Singing Accompaniment Generation in a Compositional Song Pipeline* — Tsai, Lai, Chen, Fu, Lee,
Cheng, Yang, 2026, arXiv:2602.22029 — reports Rhythm F1 0.913 / Key Acc 0.820 **because "a
pre-trained SVS module converts the lyrics and MIDI into a high-fidelity vocal track"** and the
generative model handles only accompaniment. → *Implication:* score-conditioned SVS for the
voice + deterministic bed + a mechanical gate is the published architecture, not a studio
eccentricity.

**F5. ElevenLabs Speech-to-Speech has no pitch contract.** API reference
(https://elevenlabs.io/docs/api-reference/speech-to-speech/convert) and the Comfy node
`ElevenLabsSpeechToSpeech` expose voice/stability/speed/similarity/style only; docs promise
"tone and delivery", never pitch, notes or music; singing is routed to separate products; the
`speed` knob warps timing. F0 is regenerated by the decoder, not copied. → *Implication:*
**the approved route (guide + ElevenLabs STS) is withdrawn** — it would fail the pitch gate by
construction, and no evidence says otherwise.

**F6. Explicit-F0 voice conversion exists, but only locally.** *Seed-VC* — Songting Liu, 2024,
arXiv:2411.09943 (https://github.com/Plachtaa/seed-vc): `--f0-condition true` fuses the source F0
contour, 44.1 kHz singing checkpoint, zero-shot from one clip (GPL-3.0 code; outputs unaffected).
*YingMusic-SVC* — Chen et al., GiantNetwork/UCL/ECUST/Tsinghua, 2025-12, arXiv:2512.04793:
LogF0PCC 98.12 % on clean vocals. Comfy Cloud carries **no** RVC / Seed-VC / so-vits / Vevo node
(catalog searched, 2026-09-05). → *Implication:* if a different timbre is ever wanted over a
SoulX-Singer take, Seed-VC on the 5090 inherits its pitch and onsets; nothing on the cloud does.

**F7. Comfy Cloud, inventoried without spend.** Nothing accepts MIDI, a note list or an F0
curve. `TextEncodeAceStepAudio1.5` (lyrics + bpm + keyscale + duration, `ReferenceTimbreAudio`
for timbre), `MiniMaxMusic3TextEncode` (song-level), `ByteDanceSeedAudio` (speech + line
timestamps), `ElevenLabsSpeechToSpeech`, `ElevenLabsSpeechToText` (scribe_v2, word/char
timestamps), `AudioPitchTime` (global shift/stretch). → *Implication:* the cloud's role in the
vocal path is measurement (transcribe: order, one voice) and, optionally, placement/mix via the
fx-dub shapes already in `vocal_clock.py`. The singer runs locally.

**F8. The pitch gate has a literature.** Listeners forgive the *voice* ~50 cents vs 20–30 for
instruments (*The Vocal Generosity Effect*, Hutchins, Roquet & Peretz, 2012, Music Perception
30(2)); ±50 cents is the criterion that tracks lay judgments (Larrouy-Maestri, 2018, Music &
Science); mistuning (global offset) and imprecision (scatter) are separate failure modes
(Pfordresher & Brown, 2007, Music Perception); the perceived pitch of a vibrato tone is its mean
f0 (Sundberg, JASA); MIR's note convention is 50 ms + 50 cents (`mir_eval.transcription`, Raffel
et al., 2014); trained singers hold ~20–30 cents, poor-pitch threshold ~100 cents (Dalla Bella,
2015; Pfordresher & Mantell, 2014). Trackers (SwiftF0 benchmark, Nieradzik 2025,
arXiv:2508.18440): SwiftF0 90.2 % RPA@50c mean, RMVPE 87.2 % (96.0 % on vocals), CREPE 85.3 %,
pYIN 78.7 %; SwiftF0 runs on CPU (ONNX), 16 ms hop. Objective metrics under-predict human
judgment (SingMOS-Pro, Tang et al., 2025, arXiv:2510.01812) → the gate is a floor, never the
quality claim.

**F9. The local model-knowledge KB has no singing-synthesis category at all** (`audio.md`,
27 models: music, separation, TTS). Stale by omission, not by error. → *Implication:* add an
SVS/SVC slice (SoulX-Singer, DiffSinger-OpenVPI, VocalRender, TCSinger 2, Seed-VC,
YingMusic-SVC, Vevo2) with licenses; owner: readouts.

## Architectural lock (proposed)

1. **Singer = SoulX-Singer, local on the 5090**, score mode, fed from
   `scores/amazing-grace.score-clock.v1.json` (midi + t_sec + dur_sec per syllable, lyrics),
   zero-shot timbre from the Kokoro lock or any approved female clip. Fallback #2: DiffSinger
   (OpenVPI) with an explicitly commercial-permissive English voicebank. Fallback #3: none of the
   cloud models — F3/F5/F7.
2. **Timing gate unchanged**: |vowel onset − t_sec| ≤ 40 ms, measured on the artifact
   (`vocal_clock.py verify`). If SoulX-Singer drifts on a syllable, the bag-of-takes placement
   (`plan` → `place`) re-pins it; the instrument is the safety net, not the singer.
3. **Pitch gate (new, P1 → P0)**: per syllable, nucleus = [onset + max(80 ms, 15 % dur),
   offset − 50 ms], whole vibrato cycles for held notes; SwiftF0 primary (CPU), pYIN second
   opinion; cents re: score midi, confidence-weighted mean + median octave tripwire (|mean −
   median| > 40 c ⇒ untrackable, not out-of-tune); **fail > 50 cents, warn > 25**; global median
   offset fail > 20 cents; per-note SD warn > 30; `mir_eval` COnP/COnPOff for comparability.
4. **Bed and mix unchanged** (offline bounce, headroom-staged mix). Cloud used for transcribe
   (order / one voice) and optional placement/mix.
5. **Provisioning**: stand SoulX-Singer up via engine-room / a readouts recipe, weights under
   `E:/AI-Models/hf-cache` (HF_HOME), VRAM watchdog ceiling respected; VRAM need is unpublished —
   measure before any paid run (validate-instrument-before-paid-runs).
